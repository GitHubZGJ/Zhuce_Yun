## 1 演示前准备

1. 双击 `scripts\start.bat`，确认终端显示服务已启动，记录 PID。
2. 访问 `http://127.0.0.1:8000`，确认登录页正常。
3. 准备一个浏览器窗口和一个终端窗口，终端用于展示测试或日志。
4. 关闭无关通知与弹窗，浏览器缩放保持 100%。
5. 如需重置数据，执行 `backend\seed.py --reset`，再刷新页面。

## 3 关键话术

### 3.1 项目定位

“这是一个面向施工项目部与检测机构的 Demo，不是纯 CRUD。它把工程检测业务闭环和 AI 协作治理放在同一个系统里：业务侧保证数据能录、能判、能看；治理侧保证 AI 产出可分级、可评分、可复盘。”

### 3.2 自动判定

“判定不是简单大于小于。系统区分 GTE 和 LTE，先把标准值与实测值保留两位小数再比较，避免浮点边界误差。31 大于 30 合格，29 小于 30 不合格；含水率这类上限指标用 LTE。”

### 3.3 AI 可靠性

“我们不是笼统说 AI 好用或不好用。每个任务从正确性、完整性、可运行性、可维护性、合规与安全五个维度打 0 到 5 分，加权得到 0 到 100 的失效分。全项目 24 个任务平均 13.4 分，综合可靠性 85.3；但实现与测试阶段只有 62.8，是维护重点。这就是为什么维护报告要单独分析这个阶段。”

### 3.4 缺陷帕累托

“25 条缺陷记录累计发生 68 次。前四类占 76.5%，第五类让累计过 80%。所以维护资源优先投在需求口径、接口契约、前端联调和数据模型，而不是平均撒开。”

### 3.5 AI 分级

“L1 是 Agent 自动完成，但有自动门禁和 10% 抽检；L2 是 Agent 出草稿、人逐项复核；L3 是纯人工，Agent 只能辅助检索。分级不是给 AI 贴标签，而是明确谁对结果负责。”

## 4 现场操作提示

- 新建项目时，项目编号可用 `DEMO-2026-001`，名称“演示临时项目”，保存后表格第一行可见；删除时确认框点“删除”。
- 检测记录预览不需要选择样品，只填标准值和实测值即可看到判定；正式提交才需要选择样品。
- 不要在现场修改种子数据中的关键记录；如果误操作，可刷新或重新执行种子脚本。
- 如果端口 8000 被占用，启动脚本会明确提示，不要反复双击。先执行 `scripts\stop.bat`，或换端口 `set ZHCE_PORT=8010` 后启动。
- 如果图表未加载，先确认接口 200，再刷新页面；E2E 已验证 1440×960 视口。

## 5 常见问题与回答

### Q1 为什么用 SQLite，而不是 MySQL 或 PostgreSQL？

A：这是课程 Demo，SQLite 零部署、单文件、便于批改与复现；系统使用 SQLAlchemy 与 Alembic，替换 PostgreSQL 主要改连接串与迁移方言。生产环境会选 PostgreSQL，并补充连接池、备份与并发控制。

### Q2 AI 评分是否主观？如何保证公平？

A：评分确实含人工判断。我们做了三件事：给出 0/2/4/5 锚点；FS ≥ 40 由第二人复核；评分与证据绑定，执行 Agent 不能自评。后续会做双人独立评分与一致性检验。

### Q3 可靠性 85.3 是怎么算的？

A：综合可靠性等于 0.6 乘以（100 减平均失效分）加 0.4 乘以一次通过率乘 100。全项目平均失效分 13.4，一次通过率 83.3%，得到 85.3。这个公式同时惩罚高失效和反复返工。

### Q4 为什么不把所有任务都交给 AI？

A：业务口径、权限、评分阈值、验收结论属于高风险决策，AI 可以给建议但不能签字。系统把这类任务定为 L3，责任在人。L1 也不是无人负责，而是人负责规则和门禁。

### Q5 测试覆盖率 88%，剩下 12% 是什么？

A：主要是少数删除分支、异常兜底、静态资源路由和部分 AI 删除接口。我们用 E2E 补了真实浏览器路径，但覆盖率不等于质量，关键边界和负向用例优先。

### Q6 系统最大的不足是什么？

A：三个：SQLite 并发能力有限；JWT 没有刷新令牌与吊销；AI 评分的证据采集仍偏手工。维护报告已把它们列为残余风险，并给出下一周期方案。

### Q7 如果让你继续做，下一步做什么？

A：先把重复提交拦截与错误码映射补完；再引入刷新令牌与审计日志；然后把 CI 接入测试、E2E 与图表生成；最后把评分证据自动关联到任务，降低人工采集成本。

## 6 故障兜底

| 故障 | 处理 |
|---|---|
| 服务未启动 | 检查 `.run/server.err.log`；确认 8000 端口；重新执行启动脚本 |
| 登录失败 | 确认使用演示账号；数据库是否被重建；查看网络面板响应 |
| 页面空白 | 确认前端构建产物存在；查看浏览器控制台与 `/api/health` |
| 图表空白 | 确认 `/api/dashboard/overview` 与 `/api/ai/stats` 返回 200 |
| 数据被改乱 | 执行 `seed.py --reset` 恢复演示数据，再刷新 |
| 时间不够 | 跳过项目 CRUD 与用户管理，保留看板、自动判定、AI 总览、帕累托、分级机制五个重点 |
