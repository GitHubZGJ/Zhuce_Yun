# AI 分级机制表

> 项目：筑测云 · 工程检测数据管理平台  
> 文档版本：v1.0  
> 日期：2026-11-06  
> 对应要求：构造 L1/L2/L3 分级机制，并按可行性、需求、总体设计、详细设计、实现、维护六个阶段拆分 AI 任务

## 1 分级定义

| 等级 | 名称 | 定义 | Agent 的产出 | 验收方式 | 人的职责 | 本项目任务数 |
|---|---|---|---|---|---|---:|
| L1 | Agent 自动完成 | 边界清晰、输入输出可结构化校验、错误可自动回滚的工程化任务 | 直接生成可用产物 | 自动门禁全部通过，并按 10% 抽检 | 制定规则与门禁，不逐项审阅 | 14 |
| L2 | 人机协作 | 存在业务歧义、体验取舍或跨模块协调，Agent 可产出高质量草稿但需人确认 | 草稿、候选方案、初版文档 | Agent 草稿 + 人工逐项复核并签字 | 澄清需求、校准口径、修改产物并承担最终责任 | 10 |
| L3 | 纯人工完成 | 高风险、强合规、强责任或涉及真实业务判定的任务，Agent 仅可辅助检索 | 不直接产出交付物 | 人独立完成并经第二人复核 | 决策、编写、复核与签署全流程负责 | 0（未登记为 AI 任务） |

L3 任务并非没有发生，而是不进入“AI 任务台账”计数。纯人工任务包括选题范围与验收口径确认、检测判定标准确认、失效评分口径定稿、权限与审计要求确认、验收测试结论与发布评审等。

## 2 分级原则与门禁

### 2.1 分级原则

1. **可验证性优先**：能用编译、测试、Schema 校验、静态检查自动验收的任务，优先归为 L1。
2. **歧义与责任决定等级**：涉及业务口径、权限、合规、验收结论的任务，至少为 L2；需要签署或承担责任的，归为 L3。
3. **失效可逆**：产物出错后能低成本回滚或替换的，可归 L1；一旦进入交付物就难以发现错误的，升级为 L2 或 L3。
4. **跨模块协调**：前后端联调、数据库迁移、部署脚本等跨边界任务，默认 L2。
5. **评分驱动调整**：任务完成后按五维失效评分复核，FS ≥ 40 上调一级，FS ≥ 60 直接转 L3。

### 2.2 自动门禁

| 门禁 | 适用等级 | 检查内容 |
|---|---|---|
| 语法与构建 | L1/L2 | Python 导入、前端构建、脚本语法 |
| 自动化测试 | L1/L2 | 单元与接口测试通过，关键负向用例包含消息断言 |
| Schema 校验 | L1/L2 | 请求与响应字段、类型、范围、枚举 |
| 数据一致性 | L1/L2 | 外键、唯一约束、统计口径 |
| 人工复核 | L2/L3 | 业务口径、权限、评分、验收结论 |
| 双人复核 | L3/高失效 | 关键结论与高风险变更 |

L1 不是“无人负责”，而是“人负责规则与门禁，Agent 负责执行”。L2 的关键是人工逐项确认，不能只看结果“能跑”。L3 的关键是责任不可转移给 Agent。

## 3 按软件工程阶段的 AI 任务拆分

### 3.1 可行性分析

| 等级 | 任务拆分 | 主要交付物 | 验收方式 |
|---|---|---|---|
| L1 | 五维评分数据汇总与雷达图绘制；技术栈候选检索与对比表初稿；成本项测算表与敏感性分析底稿 | 雷达图、对比表、成本底稿 | 脚本可运行，数据可追溯，抽检 10% |
| L2 | 经济/时间维度评分校准；风险清单与应对策略草拟；可行性结论与范围边界撰写 | 评分说明、风险清单、可行性报告初稿 | 人工确认评分依据与引用来源 |
| L3 | 选题范围与验收口径确认；最终可行性评审与签字 | 立项结论与评审意见 | 由人独立完成，第二人复核 |

### 3.2 需求分析

| 等级 | 任务拆分 | 主要交付物 | 验收方式 |

| L3 | 检测判定标准与业务口径确认；需求基线签署与变更审批 | 需求基线、变更记录 | 由人独立完成 |

## 6 升级、降级与接管规则

| 触发条件 | 处置 | 责任人 |
|---|---|---|
| FS ≥ 40 | 协作等级上调一级，人工重做或深度修正 | 任务负责人 |
| FS ≥ 60 或涉及权限、评分口径、验收结论 | 直接转 L3，执行根因分析并阻断发布 | 项目负责人 |
| 同一类任务连续 2 次失败 | 人工接管，Agent 退出该任务 | 任务负责人 |
| 重试次数 ≥ 2 仍不达标 | 人工接管并调整提示词或流程 | 开发负责人 |
| 连续 3 个同类任务 FS < 20 且门禁稳定 | 可申请降一级 | 项目负责人 |
| 人机协作任务 | 留存 Agent 草稿、人工修改记录与复核人 | 任务负责人 |

升级由任务负责人提出，项目负责人确认；降级需要连续证据，不能因为一次成功就放宽。所有调整记录在任务台账备注中。

## 8 与作业要求的对应

| 作业步骤 | 主要 AI 等级 | 人机分工要点 |
|---|---|---|
| 可行性分析 | L1 + L2 + L3 | Agent 做数据与图表，人确认评分依据与立项结论 |
| 需求分析 | L1 + L2 + L3 | Agent 整理故事与用例，人确认业务规则与基线 |
| 总体设计 | L1 + L2 + L3 | Agent 搭骨架与画图，人定选型与安全边界 |
| 详细设计 | L1 + L2 + L3 | Agent 生成模型与初稿，人定算法口径与权限模型 |
| 实现与测试 | L1 + L2 + L3 | Agent 写样板与测试骨架，人联调、验收与发布 |
| 维护复盘 | L1 + L2 + L3 | Agent 统计与聚类，人做根因、评级与回滚决策 |

## 9 结论

本项目形成了可执行的 AI 分级机制：L1 负责可自动验收的工程化任务，L2 负责人机协作的草稿与联调，L3 负责高风险决策与签署。实际 24 条 AI 任务中，L1 14 条、L2 10 条，4 条高失效任务均被识别并进入复盘。分级不是给 AI 贴标签，而是把“谁对结果负责”写清楚；失效评分则把“返工成本”量化，二者共同构成可监管的 AI 协作方式。
